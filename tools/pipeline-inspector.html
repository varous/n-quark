How this works

On Run it sends POST {base}/v1/signals/youtube/channels/{id}/ingest?trace=true and renders the trace array it returns — one card per stage, built from the live { stage, service, input, output, added } records. The gateway allows cross-origin requests; point it there (not directly at signal-service, which has no CORS).

If no backend is reachable, it shows a bundled sample trace (real T-Series output captured offline) so the page still tells the story — the status banner says which you're seeing. Stage 5 (the knowledge graph) is now live; the T-Series sample shows a node with no edges because STRONG_IN region edges come from Google Trends demand — run a Trends query to see them. Stages 6–9 are still scaffold placeholders because those services aren't built yet, so they aren't part of the live trace.

Note: each run appends observations (they're immutable/append-only by design), and in mock mode the classifier uses MusicBrainz's mock catalog.
